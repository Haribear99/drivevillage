# DRIVE VILLAGE

**내 차의 실제 주행거리와 정비 주기로 자라고, 지난번 이후의 여정이 주차(P단)하는 순간 한 장면으로 정산되는 차량 전용 코지 마을.**

Pleos Connect(Android Automotive OS)용 **정차 중 전용** 앱이다. 주행 중에는 화면·소리·알림이 모두 0이다(fail-closed).
2026 현대자동차그룹 차량용 앱 개발 공모전 1차 제출용 MVP(현재 제출 APK 0.1.4, 처음 접수본은 0.1.2). 마을·주민·대사는 팀 오리지널 설정이고, 0.1.3부터 마을 그래픽은 AI 생성 이미지를 쓴다(아래 '그래픽 출처').

## 실행 방법

| flavor | 용도 |
|---|---|
| `pleos` | 실제 차량 신호(AAOS `GEAR_SELECTION`·CarUxRestrictions + Pleos Vehicle SDK 2.3.2 Odometer). **제출·시연용.** 시험 입력·배속·더미 데이터 없음 |
| `demo` | 차량 없이 화면을 보기 위한 빌드. 화면 왼쪽 아래에 늘 **「시뮬레이션」** 패널(기어 P/D, 주행거리 +1/+10km, 날짜 +30일)이 보인다. 가짜 신호 코드는 `app/src/demo`에만 있다 |

```bash
./gradlew assemblePleosRelease      # 제출 APK
./gradlew assembleDemoDebug         # 시뮬레이션 APK
./gradlew testPleosDebugUnitTest    # JVM 단위 테스트
```

- JDK 17 이상, Android SDK 35. `local.properties`에 `sdk.dir` 지정.
- release 서명은 저장소 밖 키를 가리키는 `keystore.properties`(storeFile, storePassword, keyAlias, keyPassword, **커밋 금지·gitignore**)에서 읽는다. 없으면 서명되지 않은 release가 만들어진다.
- Windows에서 경로에 한글이 있으면 단위 테스트가 `ClassNotFoundException`으로 실패한다. `subst X: "<drivevillage 경로>"`로 ASCII 드라이브에 매핑한 뒤 그 드라이브에서 실행한다.

### 시연 순서(PT 스크립트 1~5·7단계 대응)

1. **기어 D** → 앱 화면이 즉시 닫히고 소리가 멈춘다. 다시 P가 돼도 저절로 뜨지 않는다(자동 실행·헤드업 팝업 금지 규정). 사용자가 앱을 다시 연다.
2. **주행거리 +N km → 기어 P → 앱 열기** → 「지난번 이후의 여정」 정산 카드(경과일·달린 거리·누적 거리·이정표) + 주민 한 문장(TTS 1회). 받은 것(재료·기념물·계절 장식)에 날짜·기억 태그가 붙는다.
3. **정비 공방**: 처음 열면 마지막 정비 시점(주행거리·날짜)과 차종 프리셋(가정값, 수정 가능)을 넣는다. 주행거리를 기준값 위로 넘기면(또는 날짜가 지나면) 부탁이 열리고, [했어요]·[예약했어요]·[다음에] 중 하나로 답한다. [했어요]에서 정비한 날·거리를 남기면 다음 안내가 그 시점 기준이 되고 공방이 증축된다.
4. **미션 탭**: 오늘의 미션 1개(기어·주행거리로만 판정), 도장 수집.
5. **꾸미기 탭(재료 도감, 0.1.4)**: 도감 칸을 누르면 아래 카드에 이름과 얻는 법(못 만남) 또는 그날의 기억과 [마을에 놓기]가 보인다. [마을에 놓기]를 누른 뒤 마을의 빈 자리(점선 원)를 누른다. 놓인 것을 누르면 그날의 기억 태그가 보인다.
7. **오프라인**: 대사는 처음부터 템플릿 렌더러라 네트워크 없이 같은 흐름으로 동작한다.

## MVP 범위

| 기능 | 규칙 |
|---|---|
| 주행 중 0 | 기어 P **AND** UX 제한 없음일 때만 마을 화면. 비P·제한·확인 불가·값 상실이면 즉시 종료하고 소리를 끊는다(되돌릴 수 없는 세션 래치, 3초 안에 판정 못 하면 종료) |
| 여정 정산(지난번 이후의 여정) | 마지막 정산 대비 주행거리 증가 ≥ 1km일 때. 카드에 직전 정산 이후 경과일·달린 거리·누적 거리·넘은 이정표를 한꺼번에 보인다. 기준값·장면 기록·재료·미션 도장을 한 파일에 원자 저장 → 같은 증가분으로 두 번 지급하지 않음(재시작 포함). 1km 미만은 다음 정산에 합산, 읽기 실패·0km는 보류, 값 역전은 다음 정산에서 한 번 더 확인된 뒤에만 기준값 재설정, 판독 중 화면이 닫히면 저장하지 않음 |
| 성장 입력 | **정산 재료**: 정산 1회 = 1개, 하루 상한 1회. **이정표 기념물**: 정산 누적 거리 1,000km마다 1개. 한 번에 여러 개를 넘어도 **정산 1회 최대 3개**(과주행 유도 방지 상한). 상한에 걸린 기념물은 사라지지 않고 다음 정산으로 넘어가며, 같은 이정표로 두 번 주지 않음. **계절 장식**: 새 계절(봄 3~5월·여름 6~8월·가을 9~11월·겨울 12~2월) 첫 정산에 1개. **정비 응답**: 0.1.4부터 재료를 주지 않는다(세 응답 모두). 공방 증축은 '했어요'에서 정비한 날·거리를 남겼을 때(증빙)만 있다(조건은 아래 정비 공방 참조). 0.1.3까지 받은 공방 톱니·정비 기념패는 그대로 남는다. 모든 아이템에 날짜·한 줄 기억 태그(프리셋 5종)·출처 이벤트 id. 기기 날짜가 시계 하한(2026-11-01)보다 이르면 정산 보류, 시계가 하루 뒤로 가도 이중 지급 없음 |
| 마을 레벨 | 성장 입력의 누적 점수: 정산 재료 1점, 계절 장식 2점, 이정표 기념물 3점, 5점마다 1레벨(팀 가정값). 0.1.3까지 받은 공방 톱니(1점)·정비 기념패(2점)도 가지고 있는 동안 그대로 센다(새로 생기지는 않는다) |
| 소리 | 탑승(움직임 없음) 1문장, 하차(장면) 1문장, 각 1회만(같은 저장에 기록). 소리 켬/끔 토글 하나가 주민 음성과 효과음(0.1.4)을 함께 끈다. 주민이 먼저 말을 거는 경로 없음 |
| 정비 공방 | 엔진오일·필터, 냉각수 **수위 점검**(월 1회 체크인), 타이어 공기압(월 1회), 타이어 위치 교환, 공조 필터, 등화 점검. km·날짜 중 먼저 도래하는 쪽으로 열림. 응답은 **했어요 / 예약했어요 / 다음에** 3개. **정비 이력과 보상을 분리**한다. 이력(다음 주기 기준): '했어요'에서 정비한 날·거리를 넣으면(현재 주행거리 이하, 직전 기준 이상, 날짜는 미래가 아니고 직전 기준일 이후) 그 값, 없으면 지금 값. 늦게 신고해도 정비 당시 값을 넣으면 다음 안내가 실제 정비 시점 기준이 된다. 보상(0.1.4): 응답은 재료를 주지 않는다. 공방 증축은 '했어요'에서 정비한 날·거리를 남겼을 때(증빙)만이고, 마지막 증축 시점(신고 당시 주행거리·날짜)에서 한 주기가 지나야 다시 커진다(과거 값으로 곧바로 재도래시켜 반복 증축할 수 없음). 예약했어요·다음에 뒤의 증빙 '했어요'도 증축 대상이다. 점등 연출과 그 시설 주민의 한 줄 인사는 '했어요'로 짝이 된 시설이 켜질 때만 있다(그 밖의 응답에는 공방 장인 도담의 한 줄 대사, 아래 0.1.4 변경). **예약했어요**: 14일 뒤 재확인. **다음에**: 500km 또는 14일 중 먼저(기준 미확인이면 날짜만, 팀 가정값 `Maintenance` 상수). 온보딩에서 **모름**을 고르면 정비 항목은 '기준 미확인': 설치 시점을 정비 시점으로 보지 않고 '점검해 보세요(기준 미확인)'로 안내한다. 응답은 사용자의 자기 신고이며 앱은 정비 여부를 알 수 없다. 사진 증빙은 폰 2단계 |
| 프리셋(가정값) | 쏘나타 DN8 HEV 통상 15,000km/12개월·가혹 7,500km/6개월(같은 그룹 참고치), 그랜저 GN7 HEV 가혹 5,000km/6개월, 투싼 NX4 가솔린 10,000km/12개월, 직접 입력. 모두 사용자가 고칠 수 있다 |
| 미션(조연) | 「주행 후 P단으로 정차하기」(기어 신호) 하나. 하루 도장 최대 1개. 페널티·점수·연속일수·과속 미션 없음. 「짧은 이동도 기록하기」는 0.1.2에서 제거(짧게 자주 열수록 받는 구조라 정산 리듬과 충돌) |
| 마을 뷰어 | 가로(2창)에서는 마을·패널 좌우, 세로(1창)에서는 위아래로 배치(방향 강제 없음). 미니어처 디오라마풍 그래픽(0.1.2까지는 Canvas 도형)의 공방(단계가 오를수록 커지고 3단계부터 깃발)·물레방아·풍차·정원·가로등(저녁·밤 점등)과 주민 3명: 공방 장인 **도담**, 여행가 **나들**, 정원사 **소이**. 슬롯 8곳에 아이템 1개씩 놓기 |
| 주민 대사 | `TripSummary`(주행거리 증가, 시간대, 마을 경과일, 열린 퀘스트, 오늘 놓은 재료)를 슬롯으로 채우는 **템플릿 렌더러**. 사실·수치는 코드가 채우고 문장 변주만 템플릿 풀에서 고른다. 렌더 결과는 검증기(남은 슬롯·입력에 없는 수치·금칙어 0)를 통과해야 하며 실패하면 안전 문장으로 대체 |
| 권한 | `android.car.permission.CAR_POWERTRAIN`(기어), `pleos.car.permission.CAR_DRIVE`(주행거리). 둘 다 normal. 차량 제어(쓰기) 없음 |

## 오늘 결정 반영(2026-11-15, v0.1.1)

1. **재진입 → 여정 정산 리듬**: '오늘의 장면'을 '지난번 이후의 여정'으로 바꿨다. 정산 카드에 직전 정산 이후 경과일·달린 거리·누적 거리·이정표를 함께 보인다. 앱을 안 연 날이 있어도 달린 거리·이정표 기념물(상한에 걸리면 다음 정산으로 넘어감)·정비 부탁은 사라지지 않고 다음 정산에 합쳐진다는 문구를 넣었다. 단, 정산 재료는 정산 1회당 1개(하루 상한 1회)라 자주 열수록 재료는 더 받는다. 그래서 카드에 "재료만은 정산할 때 하루 하나"라고 함께 적었고, '모든 보상에 손해가 없다'고는 쓰지 않았다.
2. **성장 = 다양성 기반**(0.1.1 당시): '하루 1회 2개, 거리 무관' 지급을 없앴다. 성장 입력은 정산 재료(하루 1회), 1,000km 이정표 기념물(정산 1회 최대 3개), 정비 응답 보상, 새 계절 첫 정산의 계절 장식이고, 마을 레벨은 이들의 누적 점수로 정한다. 0.1.4에서 정비 응답 보상은 없앴다.
3. **정비 = 응답만 보상 + 선택 증빙**(0.1.1 당시): 했어요 / 예약했어요 / 다음에 3개 응답, 같은 보상을 주기마다 1회. '했어요'에 정비 당시 주행거리를 넣으면 기념 장식 1개를 더 준다. 사진 증빙은 넣지 않았다(폰 2단계). 0.1.4에서 응답의 재료 보상은 없앴고 증빙 '했어요'의 공방 증축만 남겼다.
4. 0.1.0 저장 파일(하루 재료 2개)도 손상으로 보지 않고 그대로 이어서 정산한다. 0.1.0 때 누적 거리가 이미 1,000km를 넘었다면 0.1.1 정산부터 그 이정표 기념물을 정산마다 최대 3개씩 지급한다.

## 0.1.4 변경(versionCode 5, 현재 제출 APK)
- 0.1.4 APK: `apk/0.1.4/DRIVEVILLAGE_DRIVEVILLAGE_release.apk`(pleos flavor release, versionCode 5·versionName 0.1.4, 서명됨, `apksigner verify` 통과(v2 서명, 0.1.3과 같은 인증서), SHA-256 앞 8자리 `92D23D2E`). `apk/` 바로 아래의 제출 APK도 이 파일과 같다(0.1.2는 `apk/0.1.2/`로 옮김).
- **패널 크기 체계(Tier 1)**: 오른쪽 패널을 터치 64dp, 간격·가장자리 24dp, 본문 24sp(카드 제목 28sp, 강조 수치 32sp)로 다시 짰다. 64dp·24dp·24sp는 Google의 주차 중 앱 품질 가이드 Tier 1을 팀이 참고한 값이며, **Pleos 심사 기준이 아니다**. 이와 별도로 `ui/Dimens.kt`에 둔 절대 하한(글자 20sp, 터치 48dp)은 그 가이드의 값이 아니다. 20sp 하한은 팀 판단이고, 48dp는 일반 Material 터치 하한을 따른 것이다. 글자를 줄이지 않고 항목을 카드로 나누고 긴 설명은 누르면 펼치는 행으로 접었다. 마을 화면은 상단 바 제목 28sp·상태 24sp·버튼 64dp, 말풍선 본문 24sp다. 이름표 20sp, 저장 경고 20sp, 말풍선 머리글(주민 이름·역할) 20sp는 24sp 기준에 못 미친다(20sp 하한만 지킨다). demo 전용 시뮬레이션 패널(12~14sp)은 이 체계 밖이다.

- **폰트**: 제목·수치 Gmarket Sans Bold, 본문 Pretendard(Regular·Bold). 둘 다 SIL Open Font License 1.1 계열이고 파일은 원본 그대로다. ### 0.1.4 남은 알려진 한계
- 실차·저사양 단말의 프레임과 CPU는 측정하지 않았다(에뮬레이터 1024x768·768x1024만).
- 에뮬레이터를 `-no-audio`로 띄워 효과음·음성은 로그로만 확인했고 귀로 듣지 않았다. 실제 스피커 음량·duck 동작도 미확인.
- Pleos 오디오 포커스 매트릭스에서 MUSIC 컨텍스트끼리(MUSIC×MUSIC) 셀의 실제 값은 확인하지 못했다(USAGE_GAME이 다른 앱 음악과 만날 때의 동작 미확인).
- 앰비언트 소리(배경음)와 햅틱은 구현하지 않았다. 주간 정산 앨범도 구현하지 않았다.
- 세로 화면에서 가운데 주민(나들)이 말할 때, 마을 칸 아래 여백이 모자라 말풍선이 아래로 밀려 그 주민의 이름표 아래쪽을 일부 가린다(배율 1에서도 있고, 1.3배에서 더 많이 가린다). 말풍선 머리에 주민 이름이 있어 누가 말하는지는 보인다.
- demo 빌드의 시뮬레이션 패널이 왼쪽 아래 말풍선과 겹칠 수 있다(demo 전용, pleos에는 패널이 없다).
- 앱 화면 안에 폰트 고지가 없다(라이선스는 APK assets에 포함). Pleos 마켓 등록 시 AI 생성 에셋 정책은 여전히 미확인.

- 에셋은 IO 스레드에서 디코딩하고 준비 전에는 그리지 않는다. 주행 중 화면 0 원칙은 그대로다.
- 알려진 한계(0.1.3 당시): 물레방아·풍차의 날개가 회전하지 않았고, 흐린 시설을 눌러도 안내가 없었다. 둘 다 0.1.4에서 해결했다(회전 레이어, 시설 안내 시트). 남은 한계는 0.1.4 절에 적었다.

### 그래픽 출처
- 마을·주민·시설·재료 이미지는 ChatGPT 이미지 생성 모델로 만든 AI 생성물이며, 팀이 프롬프트와 컷아웃(배경 제거·크기 조정)을 했다. 특정 게임·캐릭터를 참조하지 않았다. 스타일 보드와 컷아웃은 `design_src/`에 있다(생성 원본은 용량 때문에 저장소에서 제외).
- 사용권: 생성 서비스 약관상 사용자에게 귀속되는 출력물로 쓰되, Pleos 마켓 등록 시 AI 생성 에셋 정책은 별도 확인이 필요하다(미확인).

## 0.1.2 변경(2026-11-15, 외부 리뷰 M4·레드팀 지적 반영)

1. **정비 기준점(M4)**: 늦게 신고해도 다음 안내가 늦어지지 않게, '했어요'에서 정비한 날·거리를 넣으면 그 값을 다음 주기 기준으로 쓴다(예: 10,000km에서 교환하고 12,000km에 신고해도 5,000km 주기의 다음 기준은 15,000km). 화면에 '정비한 날을 넣으면 다음 안내가 정확해져요'를 표시한다.
2. **보상 중복 방지 분리**: 보상은 정비 이력이 아니라 마지막 보상 시점을 기준으로 한 주기마다 1회. 과거 값을 넣어 곧바로 재도래시켜도 보상·증축은 늘지 않는다.
3. **온보딩 '모름' = 기준 미확인**: 설치 시점을 정비 시점으로 보지 않는다.
4. **응답 보상 일치**(0.1.2 당시): 세 응답 모두 같은 톱니 1개. 공방 증축은 증빙(정비한 날·거리)이 있을 때만. 문구 '정비한 날·거리를 남기면 공방이 커져요(선택)'. 0.1.4에서 응답의 재료 보상(톱니·기념패)은 없앴고 증빙 때 증축만 남겼다.
5. **미션**: 「짧은 이동도 기록하기」 제거, 「주행 후 P단으로 정차하기」만 남김. 이전 저장 도장은 '이전 미션'으로 표시.
6. **화면 방향**: manifest에 방향을 지정하지 않아 Pleos 1창에서는 세로로 실행될 수 있다. 세로면 마을(위)·패널(아래), 가로면 좌우로 놓는다. 에뮬레이터를 768×1024로 바꿔 세로 화면이 깨지지 않는 것을 확인했다.
